Teachers Portal

Blazor WebAssembly, .NET 10 Web API, Syncfusion, SQL Server, IIS

Context
Teachers needed one dashboard for feeds, mail, timetable and calendar, built for large-scale concurrent use.
Decision
Standalone Blazor WebAssembly instead of Blazor Server, with a separate .NET 10 API secured by JWT and a custom AuthenticationStateProvider.
Why
Blazor Server keeps a live SignalR circuit per user on the server. Moving the UI to the browser keeps server load flat at peak times.

Microsoft Entra ID single sign-on In progress

Entra ID, OWIN, ASP.NET WebForms, .NET 10

Context
An established WebForms login had to move to Microsoft sign-in without locking anyone out.
Decision
A phased rollout: users matched by their immutable Entra object ID, and an API that accepts both Entra tokens and legacy JWTs.
Why
Existing logins keep working during the migration, so each phase can ship on its own.

One codebase, 100+ databases

SQL Server, C#

Context
Each school branch and customer has its own SQL Server database on a shared instance.
Decision
Data access designed so the same application code serves every branch and client database.
Why
New features ship once instead of per branch, and every database stays isolated.

Schema audit and repair

SQL Server

Context
Core teacher and student-set tables had grown without enforced relationships.
Decision
Audited the schema and shipped a corrected script: foreign keys, indexes on FK columns, uniqueness and concurrency controls, and fixed type mismatches.
Why
The database now rejects bad data itself instead of relying on every screen to check.
